Appendix Q — The Codebase

A catalog of the programs behind the results on this site: what each one does, what it established, and how to re-run it. The published source lives in the code/ directory of the site repository.

Why publish the code. A computation's output is only as trustworthy as the program that produced it — and a program the reader cannot see is an assertion, not evidence. These scripts are published so the audit trail does not depend on trusting their author: anyone can re-run them. Running a script establishes a computed result (CHECKED); it does not constitute a proof (CP). The scope labels used below follow the site's standard key.

Q-2. The book validation scripts

Each book's page carries machine-checked assertions, and the scripts that check them ship with the site in validation/book*/ (verify_bookN.py, plus make_graphs.py and test_embeds.py where the book needs them). The pattern: the script prints its own scope-counted summary and exits 0 only if every check passes — the page footer reports the script's own numbers, not a hand count. Verified example: verify_book8.py executes 42 check executions with scope counts CP=45, SC=5, NC=22 (72 total scope attributions), confirmed by a fresh exit-0 run — static call-site counting undercounts it, which is why the runtime summary is the number of record.

Q-4. The R Theory database

The theorem database behind the site's status tags (code/database/):

  • schema.sql — the database contract.
  • rtheory.py — the CLI: init, import-status-registry, set-status, add-prose, link-prose, export-feeds, render-ledger.

Q-5. The pre-computed tables

The numerical tables the books cite (17 entries, ~802 MB, cataloged in TABLES.md with manifest.json): the E8 30380 full table and R1/R2/R3a/R3b in the current tuning (one-sided sigma-3 fix, orthonormal Sym²(128), U-basis with the U-7 caution). The tables page carries the downloadable CSVs; the large binaries are available on request. The tables are data products of the proving-ground code above, not of separate generators shipped here.

Q-6. How to re-run

The proving-ground scripts need Python 3 with NumPy (and SciPy for the B-5 indicator). The key checks, in dependency order:

python3 code/proving-ground/verify_independent.py   # from-definitions rebuild + spectrum
python3 code/proving-ground/b2_projector_check.py   # Lagrange projectors on C'
python3 code/proving-ground/b6_weyl_check.py        # exact Weyl dimensions
python3 code/proving-ground/b1_module12_image_check.py  # B-1 image check (needs the forms data)
python3 code/proving-ground/b5_reality_check.py     # B-5 reality indicator (needs scipy)

The B-1 scripts consume the pre-computed form arrays from the September 2026 runs; everything else builds its objects from the definitions in the script itself. The original Wolfram Language modules are not published here — the NumPy ports are the runnable record.

Q-7. What is not in the repository

  • Raw data products — .npy/.npz arrays, run logs, and the pre-computed table binaries are not shipped; their provenance is described above.
  • Machine-specific material — Wolfram Engine licensing and the deployment-only pieces are environment, not source, and are not published.
  • Frozen runs — the scripts are pinned to the September 2026 runs they document. Re-running on a different machine or library version should reproduce the numbers; if it does not, that is a finding, not a failure of the record.
